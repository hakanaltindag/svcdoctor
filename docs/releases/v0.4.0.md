# svcdoctor v0.4.0

The previous published release is **v0.3.3**, which diagnosed PostgreSQL and Apache Kafka. These
notes cover everything user-visible since then.

**v0.4.0 adds two service families and a way to run many targets at once.** Redis/Valkey and
RabbitMQ/LavinMQ each get a complete BASIC journey, and `svcdoctor run --config` measures every
target a configuration file declares. It also closes a disclosure defect in shareable reports and
corrects how the fleet path classified configuration errors.

No schema changed. `schemaVersion` is still `1` for both documents, and every existing
invocation behaves exactly as it did in v0.3.3.

## Highlights

- **Redis and Valkey diagnosis.** `svcdoctor diagnose redis` walks DNS, TCP, TLS, the RESP
  capability exchange, authentication and one `PING`. It names no key and reads no keyspace.
- **RabbitMQ and LavinMQ diagnosis.** `svcdoctor diagnose rabbitmq` walks one AMQP 0-9-1
  connection through `Connection.Open-Ok` for the virtual host you name. It opens no channel and
  calls no management API.
- **Multi-target runs.** `svcdoctor run --config services.yaml` measures every declared target,
  bounded and independent, and wraps their reports in one aggregate document.
- **Credential references.** A configuration names a credential by environment variable or by
  file path. A plaintext password cannot be written into the file at all.
- **Shareable aggregate reports fail closed**, which they did not before.
- **A public documentation set**: quickstart, configuration, output, CI, and a security policy.

## Redis and Valkey

One command diagnoses both. Which one answered is read from the endpoint's own reply, so typing
`redis` is not a claim about what is there.

- `AUTH` password-only and `AUTH <username> <password>`. The two forms are not equivalent against
  a `nopass` user, and svcdoctor sends the form you asked for rather than substituting `default`.
- Cluster mode is **observed and reported**. Cluster topology is not measured: no node is
  discovered, no slot coverage is checked, no advertised address is probed.
- A Sentinel endpoint is **detected and the run stops there**, before any credential is sent.
  Sentinel itself is not diagnosed.
- The credential is sent at most once, in one `AUTH`, and only over a channel whose peer identity
  was verified. Neither a loopback nor a private address changes that.

## RabbitMQ and LavinMQ

- SASL `PLAIN` only. svcdoctor never selects `ANONYMOUS`, never synthesizes a username, and never
  falls back to another mechanism.
- The terminal boundary is `Connection.Open-Ok` for the requested virtual host. Reaching it does
  not prove queue existence, permissions, cluster health or message delivery.
- `--step-timeout` must exceed 3s, because RabbitMQ delays several refusals by exactly that long
  and a shorter budget reports the delay as a local timeout instead of the refusal it is.
- Behind a load balancer svcdoctor cannot say which node answered: every node in a cluster
  reports the same cluster name.

## Multi-target runs

```sh
svcdoctor run --config services.yaml
```

One strict YAML document with its own `version: 1`, an explicit `id` per target, and a
service-owned `config` node. `--config`, `--timeout`, `--concurrency`, `--output` and
`--shareable` are the only flags: there is deliberately no `--host` and no `--target`, because a
flag that edited one target would mean the file no longer describes the run.

- **Targets are independent.** One target's failure never stops another, there is no dependency
  ordering, and svcdoctor draws no conclusion across targets.
- **Results appear in declared order**, whatever order they finished in.
- **`--concurrency` bounds targets, not sockets.** 1-16, default 4.
- The aggregate is a separate document with its own `schemaVersion`. It **wraps** target reports
  and never merges them: an embedded report is byte-identical to the same single-target run.
- Four execution states — `COMPLETED`, `NOT_STARTED`, `CANCELLED`, `EXECUTION_FAILED` — are
  orthogonal to the evidence states. A rejected password is a **COMPLETED execution** whose
  report carries the failure.

## Credentials

`password:` names a source and never holds a value:

```yaml
credentials:
  username: svcdoctor
  password:
    env: ORDERS_DB_PASSWORD      # the NAME of a variable
```

```yaml
    password:
      file: /run/secrets/orders-db
```

- A **plaintext password is refused by the decoder's type**, not by a check, so it cannot be
  parsed at all.
- **No secret is cached.** Two targets naming the same variable resolve it independently.
- References are proved resolvable in a preflight pass **before any target is dialled**, and that
  pass retains no value.
- The four `diagnose` commands still take only `--password-file` and `--password-stdin`, and read
  **no environment variable at all**. `env:` exists only inside a configuration file.

## Security and hardening

- **Shareable aggregate reports now fail closed.** A run whose target failed locally could
  previously carry a raw address or a local filesystem path — such as the location of a private
  CA — into a `--shareable` report, because collection skipped targets without a report and the
  aggregate ran no residual verification. Collection now visits every result, an execution
  failure's message is replaced by a class-derived sentence rather than filtered, and the
  finished aggregate is re-read and refused if any identifying value survived.
- **A configuration error no longer reaches execution.** A zoned IPv6 host and an unreadable
  `tls.ca_file` were exiting **4** with an `INTERNAL` execution failure — telling a pipeline to
  retry a typo. Both are validated before anything is dialled and now exit **2**, matching the
  leaf commands.
- **Two-stage interrupt.** The first `SIGINT`/`SIGTERM` cancels and the run finishes truthfully
  at exit 4; a second exits 3 immediately. This also changes behaviour for the four leaf
  commands, deliberately.
- A preflight credential failure exits **2**, not 3: an unexported variable is a configuration
  error, not a svcdoctor failure.

## Compatibility

Validated against real instances with committed fixtures. Nothing below was inferred from
documentation.

| Platform | Level |
|---|---|
| PostgreSQL self-hosted 18 | Supported BASIC |
| Apache Kafka 4.0.0 | Supported BASIC |
| Redpanda self-hosted v25.1.9 | Supported BASIC — that version only |
| Redis 8.2.1 | Supported BASIC |
| Valkey 8.1.1 | Supported BASIC |
| RabbitMQ 3.13.7, 4.0.9, 4.2.0 | Supported BASIC |
| LavinMQ 2.3.0 | Supported BASIC |

**No managed or cloud service has been validated.** None was contacted and no cloud credential
was used at any point. Redpanda Cloud, Confluent Cloud, AWS MSK, Azure Event Hubs, RDS, Aurora,
Cloud SQL and Azure Database for PostgreSQL remain unclaimed.

svcdoctor performs `PLAIN` and `SCRAM-SHA-256` and nothing else. A platform requiring
`SCRAM-SHA-512`, `OAUTHBEARER`, `GSSAPI`, `AWS_MSK_IAM` or mTLS client certificates is not usable
with svcdoctor, however standard that mechanism is.

Full grading, including what each level does and does not say, is in
[`docs/COMPATIBILITY.md`](../COMPATIBILITY.md).

## Known limitations

Deliberate boundaries, unchanged or newly stated:

- **`--concurrency` bounds targets, not sockets.** There is no global probe semaphore, so one
  target may still open a connection per resolved address.
- **No cross-target causal diagnosis.** svcdoctor will not say Kafka is failing because
  PostgreSQL is down; it measured two endpoints and has no evidence of a relationship.
- **No topology discovery.** Kafka's advertised-broker sweep is credential-free transport
  probing, not topology. Redis cluster topology and RabbitMQ clustering are not measured.
- **Terminal output does not wrap.** A finding's detail can exceed 250 columns, and responsive
  rendering is deferred.
- **A single-target JSON report carries no completeness flag.** Whether execution finished is
  reported by the exit code; use `run --config` if you need it in the file.
- No monitoring, baselines, thresholds, remediation, retries or protocol fallbacks.
- No scoped IPv6: a zone identifier such as `fe80::1%en0` is refused.
- No Markdown or HTML output, no colour, no shell completion.

## Upgrade notes

**No breaking change to any v0.3.3 command.** `diagnose postgres` and `diagnose kafka` keep their
flags, defaults, output and exit codes, and the report schema is unchanged at `schemaVersion 1`.

Three behaviours changed and are worth knowing:

1. **A second Ctrl-C now force-quits** with exit 3. Previously it was swallowed.
2. **PostgreSQL refuses `--tls-ca-file`, `--tls-server-name` and `--tls-insecure` under
   `--tls disable`**, as Kafka always did. Three previously-accepted invocations now exit 2; all
   three were inert.
3. **A preflight credential failure exits 2**, where it previously exited 3.

## Install

```sh
go install github.com/hakanaltindag/svcdoctor/cmd/svcdoctor@v0.4.0
```

```sh
docker run --rm ghcr.io/hakanaltindag/svcdoctor:v0.4.0 --version
```

Pin the digest for anything that matters. There is deliberately no `latest`, no `v0` and no
`v0.4` tag: a moving tag has no reproducible identity.

A `CGO_ENABLED=0` macOS binary uses Go's own resolver, which does not consult `/etc/resolver/*`
or mDNS. If you use split-horizon DNS, run with `GODEBUG=netdns=cgo` or use the container image.
